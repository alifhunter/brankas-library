<div className="gs-page">

  <span className="gs-eyebrow">Get Started</span>
  <h1>Install and use the design system in your app.</h1>
  <p>
    Choose your runtime, install the packages, wire up tokens, and import a component. Both web
    and native consume the same <code>@brankas/tokens</code> source of truth — colors, spacing,
    typography, and shadows stay aligned across platforms.
  </p>

  <div className="gs-tabs">
    <div className="gs-tab">
      <strong>Web (React)</strong>
      <p>
        Use <code>@brankas/react</code> in Next.js, Vite, Remix, or any React app. CSS variables
        drive theming; no bundler-specific config required.
      </p>
    </div>
    <div className="gs-tab">
      <strong>Mobile (React Native)</strong>
      <p>
        Use <code>@brankas/native</code> in any React Native app (bare or Expo). Tokens compile to
        plain JS objects consumed by <code>StyleSheet.create</code>.
      </p>
    </div>
  </div>

  <h2>Web — React</h2>

  <h3>1. Install</h3>

  <pre>{`pnpm add @brankas/react @brankas/tokens`}</pre>

  <p>Peer dependencies you likely already have:</p>

  <ul className="gs-list">
    <li><code>react</code> ≥ 19</li>
    <li><code>react-dom</code> ≥ 19</li>
  </ul>

  <h3>2. Import tokens once at the app entry</h3>

  <pre>{`// app/layout.tsx (Next.js) or main.tsx (Vite)
import '@brankas/tokens/tokens.css';`}</pre>

  <p>
    This injects every CSS variable (<code>{'--brankas-color-*'}</code>,{' '}
    <code>{'--brankas-spacing-*'}</code>, <code>{'--brankas-typography-*'}</code>) at{' '}
    <code>:root</code>. Everything downstream reads from these — change one variable and the
    whole system shifts.
  </p>

  <h3>3. Use components</h3>

  <pre>{`import { Button, Toaster, toast } from '@brankas/react/desktop';

export default function Page() {
  return (
    <>
      <Toaster position="top-right" />
      <Button
        variant="primary"
        onClick={() => toast.success('Saved')}
      >
        Save changes
      </Button>
    </>
  );
}`}</pre>

  <div className="gs-callout">
    <strong>Tree-shaking note.</strong> Import from <code>@brankas/react/desktop</code> (or
    <code>/shared</code>) rather than the package root so bundlers only pull what you use.
  </div>

  <h2>Mobile — React Native</h2>

  <h3>1. Install</h3>

  <pre>{`pnpm add @brankas/native @brankas/tokens react-native-svg`}</pre>

  <p>Peer dependencies:</p>

  <ul className="gs-list">
    <li><code>react</code> ≥ 19</li>
    <li><code>react-native</code> ≥ 0.80 (New Architecture / Fabric recommended)</li>
    <li><code>react-native-svg</code> ≥ 15</li>
  </ul>

  <h3>2. Use the theme directly — no CSS bundle</h3>

  <p>
    Tokens compile to plain JavaScript. The <code>@brankas/native</code> package re-exports them
    pre-shaped for React Native (hex colors, numeric spacing, RN shadow objects):
  </p>

  <pre>{`import { color, spacing, radius, typography, shadow } from '@brankas/native';

const styles = StyleSheet.create({
  card: {
    backgroundColor: color.background.default,
    padding: spacing[16],
    borderRadius: radius[12],
    ...shadow.mobile.selection, // shadowColor/Offset/Opacity/Radius + elevation
  },
});`}</pre>

  <h3>3. Use components</h3>

  <pre>{`import { Button } from '@brankas/native';

export function PaywallScreen() {
  return (
    <Button
      variant="primary"
      onPress={() => navigate('Checkout')}
    >
      Continue
    </Button>
  );
}`}</pre>

  <div className="gs-callout">
    <strong>Variants.</strong> The native Button ships seven variants: <code>primary</code>,{' '}
    <code>secondary</code>, <code>tertiary</code>, <code>tertiaryInvert</code>,{' '}
    <code>tertiaryBlue</code>, <code>tertiaryRed</code>, and <code>glassmorphism</code>. See{' '}
    <strong>Mobile UI → Button</strong> for the full matrix.
  </div>

  <h2>What if I need to extend tokens?</h2>

  <p>
    Tokens are defined in <code>packages/tokens/source/</code> using the W3C Design Tokens Format
    (<code>*.tokens.json</code>). The build script generates the TS exports, CSS variables, and
    the docs you're reading now.
  </p>

  <p>
    If a value doesn't exist in <code>@brankas/tokens</code>, propose it in a tokens PR rather
    than hard-coding the literal in your component. See <strong>Contribute</strong> for the
    workflow.
  </p>
