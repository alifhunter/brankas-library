  <ul className="intro-list">

    <li><code>Name.css</code> (web) or <code>Name.styles.ts</code> (native) — scoped styles using semantic tokens</li>
    <li><code>Name.test.tsx</code> — vitest (web) or jest (native) + Testing Library coverage</li>
    <li><code>Name.stories.tsx</code> — the Storybook stories you see in this sidebar</li>
  </ul>

  <h2>Conventions</h2>

  <h3>Tokens, not literals</h3>
  <p>
    Every color, font, spacing, and radius pulls from CSS custom properties so theming is a
    one-line swap. If you see a hex code in component CSS, that's a bug — file it.
  </p>

  <h3>Controlled and uncontrolled</h3>
  <p>
    Stateful components (Tabs, DatePicker, Search, Toggle, Checkbox, Pagination, etc.) support
    both forms via the standard <code>value</code> / <code>defaultValue</code> + <code>onChange</code>{' '}
    pattern. Pick whichever fits your app.
  </p>

  <h3>Accessibility is non-negotiable</h3>
  <p>
    Every interactive component ships with the right ARIA semantics, keyboard support, focus
    management, and <code>prefers-reduced-motion</code> handling. The Storybook a11y addon catches
    regressions during development.
  </p>

  <h2>Tools we ship with</h2>

  <ul className="intro-list">
    <li><strong>Vitest</strong> — every component has a test file under <code>{'*.test.tsx'}</code>.</li>
    <li><strong>Storybook a11y addon</strong> — axe-core runs against every story automatically.</li>
    <li><strong>Storybook MCP addon</strong> — Claude Code can list, search, and read stories.</li>
    <li><strong>Figma MCP</strong> — components are mapped to their Figma source frames.</li>
  </ul>
